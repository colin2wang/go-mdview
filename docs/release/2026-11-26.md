# mdview Release 2026-11-26

Version: 2026-11-26
Branch: master
Base: Wails v3.1.0 migration

## Highlights

- **Dual Mermaid rendering engine** — `mermaid` blocks can now be rendered by the classic Mermaid.js engine or the new lightweight **Pele** engine (`mermaidEngine` setting, default `pele`). Pele switches light/dark themes instantly via CSS variables, and falls back to Mermaid.js if loading fails. A per-card engine dropdown in diagram headers stays in sync with the global setting.
- **Copy diagrams as images** — the copy button on a diagram card rasterizes the rendered SVG to a PNG and writes it to the system clipboard as a bitmap (Windows CF_DIB). When the source view is shown, the button copies the Markdown source instead. Mermaid's `foreignObject` output is converted to native `<text>` in the rasterization copy so WebView2 canvases are not tainted.
- **Reworked scroll sync** — split view scroll synchronization now uses a block-level alignment table (single-lexer anchors shared by both panes), with interpolated mapping, saturation self-healing, and echo suppression to prevent feedback loops. In edit mode sync is one-way (source → preview).
- **Titlebar navigation** — internal back/forward history buttons in the title bar; external links open in the system browser instead of the WebView.

## Fixes

- Cap Mermaid.js diagrams at `min(62vh, 680px)` height (width re-derived from the viewBox), so large charts no longer overflow the viewport. Pele output is unaffected.
- Mermaid node labels survive SVG sanitization.

## Internal

- Pele is vendored locally at an exact version (`pele@1.13.0`, `frontend/public/static/pele.global.js`); all rendering libs stay offline.
- Pele output goes through a dedicated sanitizer config (`peleSvgConfig` + `stripSvgStyleUrls`), with regression cases in `sanitize-check.mjs`.
- Settings: new `mermaidEngine` field, normalized across `settings.json` and `mdview.yml`.
- New `App.CopyImage` binding; bindings regenerated.

## Upgrade Notes

- The default Mermaid engine is now `pele`; switch back to `mermaid` in Settings → Reading if you prefer the classic renderer.
- No config file format changes; existing `settings.json` / `mdview.yml` are picked up as-is.
