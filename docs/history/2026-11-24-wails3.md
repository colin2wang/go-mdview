# go-mdview 升级 Wails v2 → v3.1.0 方案
Wails v3.1.0（2026-11-01 发布）是**全新架构**：`wails.Run()` → `application.New()` + Service 模式、`runtime.*` → 对象方法、`wailsjs/` 绑定 → `bindings/` 生成、构建从 `wails build` → Taskfile 体系（`wails3 build` 只是 `wails3 task build` 的薄封装）。迁移是"真移植"而非改版本号。以下是针对本项目的完整方案。
---
## 一、需要修改的文件总览
| 文件/目录 | 操作 | 说明 |
|---|---|---|
| `go.mod` / `go.sum` | 改 | `wails/v2` → `wails/v3 v3.1.0`，`go mod tidy` |
| `main.go` | 重写 | `wails.Run` → `application.New` + 窗口创建 + `Run()` |
| `wails.json` | 重写 | v2 扁平结构 → v3 `frontend:{...}` 块；顺带 `npm install` → `pnpm install` |
| `internal/app/app.go` | 重构 | 绑定层 Service 化：去 `ctx` 字段，`startup()` → `ServiceStartup()`，所有 `runtime.*` 换窗口/应用对象方法 |
| `frontend/wailsjs/` | **删除** | v2 生成物（`go/app/App.js`、`runtime/`）不再使用 |
| `frontend/bindings/` | 新增 | `wails3 generate bindings -ts -d frontend/bindings` 生成 |
| `frontend/src/api.ts` | 改 | 数据源从 `window.go.app.App` 改为生成的 bindings |
| `frontend/src/globals.d.ts` | 改 | 删 `window.go` / `window.runtime` 声明 |
| `frontend/src/store.ts` | 改 | `OnFileDrop` / `EventsOn` 调用点迁移 |
| `frontend/src/App.vue`（或 `index.html`） | 改 | 加 `data-file-drop-target` 属性 |
| `frontend/package.json` | 改 | 加 `@wailsio/runtime` 依赖 + `bindings` 脚本 |
| `frontend/vite.config.ts` | 核对 | dev 端口、`@wailsio/runtime` 处理，对照官方 vue-ts 模板 |
| `Taskfile.yml`（根目录） | **新增** | v3 构建入口 |
| `build/` | **新增** | `Taskfile.yml`、`config.yml`、`appicon.png`、`windows/{Taskfile.yml,icon.ico,info.json}`、`darwin/`、`linux/` |
| `build.ps1` | 重写 | `wails build` → `wails3 build` / `wails3 package` |
| `generate-icon.ps1` | 重写 | → `wails3 generate icons` |
| `tools/genicon/` | 评估 | 若只产出源 PNG 则保留，产物交给 `wails3 generate icons` |
| `README.md` | 改 | 构建命令、`Go 1.25+/1.27+` 徽章顺带统一 |

## 三、新增 build/ 构建目录（v3 构建体系核心）
v3 的构建完全由项目内 Taskfile 驱动，`wails3 build` 只是 `wails3 task build` 的别名。**最稳妥做法**：临时目录初始化一个官方模板，拷贝构建骨架过来：
```bash
wails3 init -n tmpwails -t vue-ts
# 拷贝到 go-mdview 根目录：
#   tmpwails/Taskfile.yml            （根入口，改 APP_NAME: mdview）
#   tmpwails/build/                  （Taskfile.yml + windows/ + darwin/ + linux/ + config.yml）
```
需要本地化的内容：
- `Taskfile.yml` 根入口：`APP_NAME: mdview`、`BIN_DIR: bin`（注意 **产物路径从 v2 的 `build/bin/` 变为根目录 `bin/`**，CI/安装脚本里凡是引用 `build/bin/mdview.exe` 的地方都要改）；
- `build/windows/info.json`：填产品名/版本号（生成 `.syso` 时嵌入 exe 版本资源）；
- `build/appicon.png`：放源图标（1024×1024 PNG）；
- `build/config.yml`：`dev_mode.executes` 里的前端命令统一为 **pnpm**（顺带修掉评审提过的 npm/pnpm 混用问题），Vite 端口默认 9245。
> `wails3 generate build-assets` 可从 `build/config.yml` 重新生成/刷新平台资产（NSIS 脚本、Info.plist 等）；`wails3 task --list` 可查看全部可用任务。

## 五、main.go 重写
v2 的 `wails.Run(&options.App{...})` 拆成"创建应用 → 创建窗口 → Run"三段。本项目映射：

```go
package main

import (
	"embed"
	"net/http"
	"strings"
	"github.com/wailsapp/wails/v3/pkg/application"
	"github.com/wailsapp/wails/v3/pkg/events"
)

//go:embed all:../../frontend/dist
var assets embed.FS

func main() {
	wailsApp := application.New(application.Options{
		Name: "mdview",
		Services: []application.Service{
			application.NewService(app.NewApp()), // internal/app 的绑定层
		},
		Assets: application.AssetOptions{
			Handler: assetHandler(), // 见下：/mdimg 路由 + 静态资产
		},
		SingleInstance: &application.SingleInstanceOptions{
			// 沿用 v2 SingleInstanceLock.UniqueId，保证重启互踢逻辑不变
			UniqueID: "<原锁名>",
			OnSecondInstanceLaunch: func(data application.SecondInstanceData) {
				// v2 的 OnSecondInstanceLaunch 在此等价迁移；文件路径来自 data.Args
				app.SetStartupFile(firstMdArg(data.Args))
			},
		},
	})
	win := wailsApp.Window.NewWithOptions(application.WebviewWindowOptions{
		Title: "mdview",
		Width: restoredW, Height: restoredH, // 原 GetSettings 恢复的几何
		X: restoredX, Y: restoredY,
		StartState:     application.WindowStateMaximised, // 原记忆了最大化时
		Frameless:      true,                             // 原 options.Frameless
		EnableFileDrop: true,                             // 替代 runtime.OnFileDrop（默认关闭！）
		// 原 OnBeforeClose：草稿未保存时弹 discard-modal 并否决关闭
		ShouldClose: func(w *application.WebviewWindow) bool {
			return app.ConfirmCloseDraft()
		},
	})
	// 原 runtime.OnFileDrop：Go 侧接原生拖放，转发前端
	win.OnWindowEvent(events.Common.WindowFilesDropped, func(e *application.WindowEvent) {
		paths := e.Context().DroppedFiles()
		wailsApp.Event.Emit("mdv:files-dropped", paths)
	})
	wailsApp.Run()
}

// 原 AssetServer（若是 Middleware 方式）等价改写：/mdimg 直连 imgserver，其余走 v3 资产服务
func assetHandler() http.Handler {
	fileServer := application.AssetFileServerFS(assets)
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if strings.HasPrefix(r.URL.Path, "/mdimg/") {
			mdv.ServeImg(w, r)
			return
		}
		fileServer.ServeHTTP(w, r)
	})
}
```
要点：
- `Bind` → `Services`（`application.NewService`）；`OnStartup` → `ServiceStartup`；`OnBeforeClose` → `ShouldClose`；`OnShutdown` → `ServiceShutdown`；
- 若 v2 有 `OnDomReady`，改为 `win.OnWindowEvent(application.CommonWindowEvents.DOMReady, ...)`；
- 恢复窗口几何时可用 `wailsApp.Screen` API 做越界校验（顺带落实"拔显示器越界居中"的评审建议）。

## 六、internal/app/app.go：Service 化 + runtime API 对照
**结构调整**：删除 `ctx context.Context` 字段与 `startup(ctx)`，改为：
```go
type App struct {
	app *application.App
	win *application.WebviewWindow
	// …原有字段不动（settings/store/watcher/assoc…）
}
func (a *App) ServiceStartup(ctx context.Context, options application.ServiceOptions) error {
	a.app = application.Get()
	a.win = a.app.Window.Current()
	// 原 startup(ctx) 的初始化：读设置、imgserver、watcher 等
	return nil
}
```
**方法体级映射**（覆盖 `api.ts` 里的全部 30+ 绑定；方法名保持不变可让前端改动最小化）：
| v2（runtime 包） | v3.1.0 | 对应本项目绑定 |
|---|---|---|
| `runtime.WindowMinimise(ctx)` | `a.win.Minimise()` | `WindowMin` |
| `runtime.WindowToggleMaximise(ctx)` | `a.win.ToggleMaximise()` | `WindowMaxToggle` |
| `runtime.WindowClose(ctx)` | `a.win.Close()` | `WindowClose` |
| `runtime.WindowSetAlwaysOnTop(ctx,b)` | `a.win.SetAlwaysOnTop(b)` | `WindowPin` |
| `runtime.WindowToggleFullscreen(ctx)` | `a.win.ToggleFullscreen()` | `WindowFullscreenToggle` |
| `runtime.WindowSetTitle(ctx,t)` | `a.win.SetTitle(t)` | `SetWindowTitle` |
| `runtime.OpenDirectoryDialog` | `a.app.Dialog.OpenDirectoryWithOptions(&application.OpenDirectoryDialogOptions{...}).PromptForSingleSelection()` → `.Path()` | `OpenFolderDialog` |
| `runtime.OpenFileDialog` | `a.app.Dialog.OpenFileWithOptions(&application.OpenFileDialogOptions{Title, Filters: []application.FileFilter{{DisplayName:"Markdown", Pattern:"*.md;*.markdown;*.mdown;*.mkd"}, …}}).PromptForSingleSelection()` | `OpenFileDialog` |
| `runtime.SaveFileDialog` | `a.app.Dialog.SaveFileWithOptions(&application.SaveFileDialogOptions{DefaultFilename, Filters}).PromptForSingleSelection()` | `SaveHtmlDialog/SaveSvgDialog/SaveImageDialog` |
| `runtime.ClipboardSetText(ctx,s)` | `a.app.Clipboard.SetText(s)` | `CopyText` |
| `runtime.BrowserOpenURL(ctx,u)` | `a.app.Browser.OpenURL(u)` | （若有使用） |
| `runtime.EventsEmit(ctx,name,…)` | `a.app.Event.Emit(name, data)` | watcher 通知前端 |
| `runtime.Quit(ctx)` | `a.app.Quit()` | `RestartApp`（spawn+`--wait pid` 自研逻辑不动） |
| `runtime.OnFileDrop`（若 Go 侧注册） | `win.OnWindowEvent(events.Common.WindowFilesDropped, …)` | 拖拽打开 |
- `RevealInShell`：v3 无内置"在资源管理器中显示"，**保留现有 `explorer /select` 自研实现**；
- `SingleInstanceLock` → 见 main.go 一节；`startupFile` 竞态问题（评审 3.2）顺带用 `atomic.Pointer` 修掉；
- `ToggleFavorite` 返回 `(bool, []Entry)` 建议顺带改成显式结构体——与既有评审建议一致，也避免 v3 生成绑定的多返回值形态歧义；
- `internal/mdv/*` 全部是纯领域逻辑（读文件/设置/watcher/关联/导出），**零改动**。

## 七、前端改造
**1. 绑定迁移**（删除 `frontend/wailsjs/`，生成新目录）：
```bash
rm -rf frontend/wailsjs
wails3 generate bindings -ts -d frontend/bindings   # flags: -d 输出目录、-ts、-models、-index
```
生成结构为 `frontend/bindings/<go模块路径>/app`，按 Service 组织。`api.ts` 改为：
```ts
import * as App from '../bindings/<go模块路径>/app'
// 类型直接从生成物派生 —— 顺带解决评审"手写 Api 接口会漂移"的 P3 问题
type DesktopApi = { [K in keyof typeof App]: typeof App[K] }
// mock 注入逻辑保留：isDesktop() ? desktopApi() : (await import('./mock')).mockApi
```
**2. 运行时迁移**：`frontend/wailsjs/runtime/*` 全部换成官方 npm 包：
```bash
pnpm add @wailsio/runtime
```
| v2 | v3 |
|---|---|
| `EventsOn(name, cb)` | `Events.On(name, (ev) => ev.data)` — **回调参数是事件对象，取数方式变化** |
| `EventsOff(name)` | `Events.Off(name)` |
| `runtime.OnFileDrop(cb, useDropTarget)` | 见下：Drop Zone 机制 |
| `runtime.OnFileDropOff()` | 无对应（退出时用 `Events.Off`） |
**3. 拖拽打开**（v3 机制变了，默认关闭）：
- 窗口选项 `EnableFileDrop: true`（已在上文 main.go）；
- `App.vue` 的 `app-shell`（或 `index.html` 的 `<body>`）加 `data-file-drop-target` 属性；Wails 会在拖悬停时自动加 `file-drop-target-active` 类（可替换现在自绘的 `.drop-hint`，也可以继续用现有 toast）；
- Go 侧 `WindowFilesDropped` → `Event.Emit("mdv:files-dropped", paths)` → 前端 `Events.On` 接住，走原 `openFile` 分发（md/图片/文本）。
  **4. 其他前端点**：
- `globals.d.ts`：删除 `window.go` / `window.runtime` 声明（v3 运行时自动注入 `/wails/runtime.js`，不再有 `window.go`）；`isDesktop()` 改为检测 `window._wails`（或更稳妥：绑定层加一个 `IsDesktop()` 方法）；
- `store.ts` 中 `EventsOn`（watcher 外部变更通知）迁移到 `@wailsio/runtime`；
- `TitleBar.vue`/`SettingsModal.vue` 走 `api.ts`，**方法名不变则无需改动**；
- `vite.config.ts` 对照官方 vue-ts 模板核对 dev 端口与 runtime 处理；浏览器纯 mock 模式（`window.go` 不存在）照旧可用——正好 v3 文档也说明纯浏览器模式下 Go 绑定不可用；
- `tsconfig.json` 确认包含 `frontend/bindings`；
- 无边框窗口拖拽：v2/v3 都用 `--wails-draggable: drag` CSS 变量，`TitleBar` 现有样式应能延续，回归时确认即可。

## 八、build.ps1 重写
```powershell
# ---- 旧（wails v2）----
# wails build -clean -s -ldflags "-H windowsgui" ...
# wails build -nsis
# ---- 新（wails3 v3.1.0）----
wails3 doctor
wails3 generate bindings -ts -d frontend/bindings
Push-Location frontend
pnpm install
pnpm run build          # 含 vue-tsc + vite build + sanitize-check
Pop-Location
wails3 build            # = wails3 task build：图标 → .syso → go build
# 产物：bin\mdview.exe   （不再是 build\bin\）
# 可选：NSIS 安装包（需 build/windows/nsis/ 由 wails3 generate build-assets 生成）
wails3 package
# 可选：WebView2 引导安装器（替代旧 -webview2 bootstrapper 参数）
wails3 generate webview2bootstrapper
```
注意：`wails3 build` **没有** `-platform/-o/-skipbindings/-icon/-ldflags` 等旧旗标，交叉编译/输出路径/打包全部走 Taskfile（`wails3 task windows:build`、`darwin:build:universal`、`linux:build`）。v3.1.0 新增可选项：`WAILS_PUREGO=1 wails3 build` 或 `CGO_ENABLED=0 go build -tags purego,production .`（实验性 CGO-free 构建，可顺带用于交叉编译验证）。

## 九、generate-icon.ps1 重写
v3 用一条命令产出全平台图标（flags：`-input`、`-windowsfilename`、`-macfilename`、`-iconcomposerinput`、`-macassetdir`）：
```powershell
# 源 PNG 仍可由 tools/genicon 产出（若该工具只是画 appicon.png，保留它作为源图生成器）
wails3 generate icons `
  -input        build/appicon.png `
  -windowsfilename build/windows/icon.ico `
  -macfilename  build/darwin/icons.icns
```
说明：
- `wails3 task windows:build` 在构建时已自动做"图标 + `wails3 generate syso`"（`.syso` 内嵌图标与版本资源，来源 `build/windows/info.json`），所以此脚本定位为**手动刷新**用；
- `.md` 文件关联的图标走注册表 `DefaultIcon` → mdview.exe 内嵌图标，由 syso 流程负责，**行为不变**；
- 若 `tools/genicon` 与图标源生成无关（比如还有别的用途），逐条核对其职责后再决定保留/退役。

## 十、本项目专项回归清单
| 专项 | 风险点 |
|---|---|
| 单实例 + 重启 | 锁 `UniqueID` 必须沿用旧值；重启新进程 `--wait pid` + 第二实例 `OnSecondInstanceLaunch(data.Args)` 拿到被双击的文件路径 |
| 草稿丢弃确认 | `ShouldClose` 否决关闭 → 前端 discard-modal → 确认后 `win.Close()` 的二次关闭链路要重验（关闭/重启/切换/重载四个出口） |
| 外部修改 watcher 通知 | `EventsEmit` → `app.Event.Emit`；前端回调取数从 `...data` 变 `ev.data` |
| 拖拽打开 | `EnableFileDrop` 默认关闭；drop zone 属性 + `mdv:files-dropped` 事件链路 |
| /mdimg 图片回放 | asset handler 链（`AssetFileServerFS` + 自定义 `/mdimg/` 分流）|
| 无边框窗口 | Frameless + 拖拽区 CSS 变量 + 自绘按钮三件套 |
| 窗口几何记忆 | `X/Y/Width/Height/StartState`；顺带用 Screen API 做越界居中 |
| 文件关联 | 纯 Go 注册表逻辑不受影响；exe 图标由 syso 提供 |
| "100% 离线" | v3 资产同样内存服务，无网络端口；远程拦截逻辑不受升级影响 |
## 十一、建议实施顺序
1. 装 CLI + `wails3 doctor` → 2. `go.mod` 切 v3.1.0 → 3. 拷模板生成 `Taskfile.yml` + `build/` 并本地化 → 4. 重写 `main.go` + Service 化 `app.go`（保持方法名不变）→ 5. `wails3 generate bindings` + 前端五处改造 → 6. 重写 `build.ps1` / `generate-icon.ps1` / `wails.json` → 7. `wails3 dev` 全功能手测 → 8. `wails3 build` → `wails3 package` 验产物路径与安装包 → 9. 更新 README（构建命令、Go 版本口径）。
   预计 1–2 天工作量（官方典型迁移 1–4 小时，本项目多了单实例重启、拖拽、草稿确认、/mdimg 资产分流四个自研链路需要逐一重验）。如需要，我可以直接给出 `main.go`、`app.go` 迁移后版本或新 `build.ps1` 的完整补丁。
